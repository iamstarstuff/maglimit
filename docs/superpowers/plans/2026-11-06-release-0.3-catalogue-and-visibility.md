# maglimit 0.3 (catalogue and visibility) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer "can I see this object with this telescope under this sky?" offline, with a graded verdict, a recommended eyepiece and the numbers behind it, through `explain()` and `maglimit check`.

**Architecture:** A new pure-maths `visibility.py` implements Crumey's (2014) threshold model. A new `catalogue.py` loads a bundled, trimmed OpenNGC file built by `scripts/build_catalogue.py`. A new `planner.py` joins them in `explain()`, which returns plain data for the CLI. `Telescope.sky_lim_mag()` moves onto the same model, so stars and extended objects share one set of physics.

**Tech Stack:** Python ≥3.10, standard library for the model and catalogue (`csv`, `math`, `importlib.resources`, `difflib`), argparse, pytest, uv. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-observing-planner-design.md` (§3 anti-goals, §5.2 catalogue, §5.4 visibility model, §6 layout, §8 phase 0.3, §9 tests).

**Model source:** Crumey, A. (2014), "Human contrast threshold and astronomical visibility", MNRAS 442, 2600. Preprint: https://arxiv.org/abs/1405.4209. Equation numbers below refer to this paper. Read §3.2–3.3 before Task 1.

## Global Constraints

- Don't break the v0.1/v0.2 API: names, signatures and return types stay. `test/test_limiting_mag.py` must pass **unchanged**. `lim_mag()` stays `2 + 5·log₁₀ D`.
- `sky_lim_mag()` keeps its signature but its **values change** (see Decisions). This is deliberate, and the changed tests are listed in Task 2.
- `visibility.py` is pure: plain numbers in, plain numbers out, no astropy, no numpy (spec §7 rule, so it ports to TypeScript).
- No network access in anything added here. `find_object()` never calls NED.
- Verdicts are always graded: `easy`, `moderate`, `challenging`, `very hard`, `not visible` (spec §3, §5.4c). Never a bare True/False.
- Public numeric results are plain `float` rounded to 2 decimals. `explain()` returns JSON-serialisable types only.
- OpenNGC stays CC-BY-SA-4.0 with attribution in a separate license file; the code stays MIT (spec §5.2).
- Match existing style: Google-style docstrings, one docstring per test. `uv run ruff check .` must pass.

## Decisions made in this plan (differ from or add to the spec)

1. **Crumey (2014) replaces the Clark/Blackwell table lookup in spec §5.4.** It's a published closed-form fit to the same Blackwell (1946) data, so `blackwell.csv` isn't needed and the TypeScript port shrinks to a few lines. It was tested against Bowen's measured limits (0.09 mag r.m.s., against 0.37 for Schaefer's model) and Herschel's discoveries. The prototype reproduced the paper's values; those become tests in Task 1.
2. **`sky_lim_mag()` moves to this model**, replacing the simplified 0.2 formula. Published 0.2 numbers change: 200 mm f/5 at SQM 20 with a 10 mm eyepiece goes from 14.05 to 13.32, and low power from 12.69 to 12.23. Two models giving different star limits in one package would be worse.
3. **Field factor default `F = 2`,** Crumey's notional typical value (φ = √2·F through a telescope). It's a keyword argument, not a CLI flag.
4. **Bright-core rule (calibrated, not derived).** Types `G`, `GPair`, `GTrpl`, `GGroup`, `GCl`, `Cl+N` are also tested as a core holding half the light in a quarter of the diameter (1/16 of the area, so 8× the surface brightness); the better margin wins. Without it M31 rates "not visible" in a city, because catalogue sizes reach far past what the eye sees. Crumey warns that non-uniform targets limit any such model.
5. **Verdict bands** on the margin (magnitudes above threshold): ≥ 2 easy, ≥ 1 moderate, ≥ 0.5 challenging, ≥ 0 very hard, below 0 not visible. Crumey's Herschel objects give a reference: mean margin 0.69 for those found, 0.35 for those missed.
6. **A `confidence` field** (`normal` or `low`) with `reasons`. It's `low` for the types `HII`, `Neb`, `EmN`, `RfN`, `SNR` (catalogue magnitudes are unreliable and filters aren't modelled, e.g. NGC 7000 rates too well), for an estimated magnitude or size, and when SQM < 19 (Crumey's stated limit for the sky-spectrum correction).
7. **Magnitude rule:** use V. For galaxy types, use `B − 0.76` when V is missing or `B − V` falls outside −0.2 to 2 (0.76 is the median of 3,336 OpenNGC galaxies; this fixes NGC 253's bad V of 11.11). For other types with no V, use `B − 0.76` too, flagged as estimated. Spec §5.2's 0.8 is superseded by this measured value.
8. **`corrections.csv`** fills the 7 Messier objects with no magnitude, with Wikipedia's *List of Messier objects* as the source. Each row names its source.
9. **Golden verdicts** below come from the prototype, checked against general observing experience. They are **not** from a published source yet, so Pratik should review them (see Task 5).
10. **Observer's pupil.** Crumey's `p` isn't a free observer setting: his fits pair a smaller measured pupil with a higher field factor (Bowen: 5.2 mm, F = 2.74), so changing `p` alone raises the limit, the bug fixed in 0.2. `visibility.py` stays faithful to the paper, and its tests use the paper's `p`. Public code always calls it with `eye_pupil=7.0`, and models a smaller eye by cutting the aperture to what the eye can use (`used_aperture`). At 7 mm this matches the paper exactly.
11. **At the zenith.** 0.3 ignores altitude and extinction, and the Moon, which arrive in 0.4. `explain()` output says so through a `"assumes"` entry.

## Review Focus

1. Names as people type them: `m31`, `M 31`, `M031`, `ngc224`, `NGC 0224`, `andromeda galaxy`, `C 20`. All should resolve. Pinned in Task 3.
2. Duplicate entries and unknown names: `M102` follows its duplicate to M101's object, and a typo gives a clear error with suggestions, never a crash or a wrong object. Pinned in Task 3.
3. Objects with missing data (M40, M73 have no size; any row may lack magnitude): a low-confidence answer, or a clear error if there's no magnitude. Never a traceback. Pinned in Task 4.
4. Very high magnification under a very dark sky, where the eyepiece background drops below 10⁻⁵ cd/m²: the threshold must level off, not keep improving. Pinned in Task 1.
5. `maglimit check` with no sky given, a bad name, or `--json`: clean error and exit 2, or valid JSON. Pinned in Task 6.

### Task 1: Visibility model

**Files:**
- Create: `maglimit/visibility.py`, `test/test_visibility.py`

**Interfaces:**
- Produces (all plain floats; `throughput` = transmission × (1 − obstruction²)):
  - `sky_luminance(mu) -> float`: cd/m² from mag/arcsec², `Z/ARCSEC2 · 10^(−0.4·mu)`, with `Z = 2.54e-6` lux and `ARCSEC2` = one square arcsecond in steradians.
  - `surface_brightness(magnitude, major, minor) -> float`: `m + 2.5·log10(π/4 · a · b · 3600)`, axes in arcmin.
  - `star_limit(aperture, magnification, sqm, eye_pupil=7.0, throughput=0.8, field_factor=2.0) -> float`: faintest point source (Eq. 68, cut-off Eq. 71).
  - `visibility_margin(mu_object, area, aperture, magnification, sqm, eye_pupil=7.0, throughput=0.8, field_factor=2.0) -> float`: magnitudes above threshold; `area` in arcmin².
  - `verdict(margin) -> str`.

- [ ] **Step 3: Implement.** Scotopic constants from Eqs. 26, 37, 44: `r1 = 6.505e-4`, `r2 = -8.461e-4`, `k1 = 7.633e-3`, `k2 = -7.174e-3`, `q = 0.6`. The exact calculation, which the prototype verified:

```python
d = aperture/magnification                        # exit pupil
d_min, d_max = min(d, eye_pupil), max(d, eye_pupil)
background = (d_min/eye_pupil)**2 * sky_luminance(sqm) * throughput   # Eq. 66
effective = max(background, 1e-5)                 # zero-background cut-off
ricco = (r1*effective**-0.25 + r2)**2             # Eq. 78
large = k1*effective**-0.25 + k2                  # Eq. 80
phi = math.sqrt(2)*field_factor

# star_limit, Eq. 68 with the cut-off applied:
increment = (d_max/aperture)**2 / throughput * phi * effective * ricco
limit = -2.5*log10(increment/Z)

# visibility_margin, comparing brightness increments so the cut-off works:
object_increment = sky_luminance(mu_object) * (d_min/eye_pupil)**2 * throughput
apparent_area = area*3600*ARCSEC2*magnification**2                    # Eq. 79, in sr
threshold = effective*phi*((ricco/apparent_area)**q + large**q)**(1/q)  # Eq. 77
margin = 2.5*log10(object_increment/threshold)
```

Don't round in this module; rounding happens at the public edge. Cite the equations in the docstrings.
